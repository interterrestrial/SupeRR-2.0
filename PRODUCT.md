# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The primary users are hackathon judges reviewing the final player selections. They need to verify the ranked lists, explore how the rankings change by competition mode and national team, and inspect the evidence behind a player without reading the complete technical report first.

The secondary user is the presenter, who will use the dashboard during judging and link to it from the report and presentation.

## Product Purpose

The dashboard makes the validated SupeRR Selector rankings explorable. It turns the completed 2022–2026 IPL and T20I analysis into a clear, filterable Top-10 experience while preserving the scoring, eligibility, and uncertainty rules established in Phases 3–7A.

Success means a judge can select one or both competition modes, select any combination of national teams, switch between batters and bowlers, understand the resulting leaderboard, and open the evidence for any displayed player.

## Positioning

The dashboard is a transparent evidence layer over the locked analytical model. It does not create a separate simplified score or recompute methodology in the browser. Every displayed rank, rating, qualification, explanation, and limitation traces back to validated project outputs.

## Operating Context

- Public, read-only dashboard opened from a Vercel URL or QR code.
- Used on judging laptops, presentation screens, tablets, and phones.
- Default state selects both IPL and T20I and every national team.
- Mode and National Team are both multi-select controls.
- Mode contains exactly two options: IPL and T20I. At least one must remain selected.
- National Team contains every national side represented in the supplied T20I competition mappings and supports any multi-selection.
- Selecting IPL and Australia ranks Australian players by IPL evidence. Selecting both modes and Australia applies the validated combined-rating rule to Australian players.

## Capabilities and Constraints

- Roles: Batter and Bowler.
- Ranking inputs: validated Phase 4 format and combined ratings.
- Official default state must reproduce the Phase 5 Top 10 exactly.
- Only Reliable evidence enters a leaderboard.
- Scores are ordered using unrounded values and displayed with appropriate rounding.
- A result with fewer than ten eligible players is labelled Top N eligible players.
- National-team metadata filters the population but never changes a score.
- The site uses static JSON generated by a Jupyter notebook. It requires no database, Python server, login, or writable user data.
- Player detail includes format qualification, pressure evidence, metric contributions, uncertainty, and approved Phase 6 explanations.
- Vercel is the intended host; permanent deployment is deferred until user review. Cloudflare-specific runtime and storage are out of scope.

## Brand Commitments

The product name is SupeRR Selector Season 2. The current dashboard and report use navy text, pink highlights, white surfaces and Arial typography, inspired by the original hackathon problem statement. DESIGN.md is the current dashboard styling authority. The original Phase 7 visual specification remains a historical frozen artifact. The interface must remain analytical and credible rather than promotional or game-like.

## Evidence on Hand

- Canonical Phase 7A player evidence and claim registry.
- Phase 4 batter and bowler format metrics and combined scores.
- Phase 5 official rankings and uncertainty results.
- Phase 6 pressure-versus-ordinary, format, and player explanations.
- Competition, team, and player mappings from the supplied data pack.
- A locked official-ranking signature for drift detection.

No player photographs, nationality field, or current external roster feed is supplied. National-team identity is derived from T20I mappings and an audited supplement for reliable IPL-only candidates.

## Product Principles

1. Preserve the validated model; filtering must never become silent recalculation.
2. Put the leaderboard and filters in the first viewport.
3. Keep qualification and uncertainty visible beside performance.
4. Explain empty or small result sets instead of filling them with weaker evidence.
5. Make every dashboard state reproducible and shareable.

## Accessibility & Inclusion

The dashboard targets WCAG 2.1 AA contrast, full keyboard operation, visible focus states, semantic controls and tables, reduced-motion support, and layouts that remain usable without horizontal page scrolling.
